# Health checks

Every component reports `ok`, `degraded`, `down` or `unknown`. A **quick** check is cheap and runs on every refresh of the overview; a **deep** check performs a real end-to-end test and returns a list of steps (this is what every *Test connectivity* button in the control panel runs: `POST /v1/admin/health/checks/{name}/test`). `GET /v1/health` (liveness: the process is up) and `GET /v1/health/ready` (readiness: the database answers and `runtime-trust` is not `down`; otherwise `503` with a fixed body) are the unauthenticated probes for load balancers and orchestrators; `GET /v1/admin/health` is the authenticated snapshot (`admin.health`).
