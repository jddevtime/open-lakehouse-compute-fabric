# Event types and audit actions

Events are persisted in the `events` table, served by `GET /v1/events` and the Server-Sent-Events stream `GET /v1/events/stream` (supports `Last-Event-ID`), and delivered to webhook subscriptions (see the [observability guide](../guides/observability.md)). In-process subscribers (for example the Intelligence inbox writer) are called on a delivery lane of their own, and a publisher waits for them for at most 0.5 seconds in total, so a slow subscriber cannot hold a job, query or pipeline run (`core/events.py`). Type names read `<domain>.<noun>.<verb>`; subscriptions match them with glob patterns (`job.*`, `pipeline.run.failed`, `*`).
