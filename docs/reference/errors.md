# Error codes

All API errors use one envelope:

```json
{"error": {"code": "not_found", "message": "...", "details": {}, "remediation": "...", "correlation_id": "..."}}
```

`code` is stable and machine readable; `message` and `remediation` are for people; `correlation_id` also appears in the server log and the `X-Correlation-ID` response header. Python SDK exceptions mirror these (`NotFoundError`, `PermissionDeniedError`, `ConflictError`, ...).

## Job states

| State | Terminal | Can move to |
|---|---|---|
| `accepted` | no | `cancel_requested`, `cancelled`, `failed`, `validating` |
| `validating` | no | `cancel_requested`, `cancelled`, `failed`, `queued` |
| `queued` | no | `cancel_requested`, `cancelled`, `failed`, `provisioning`, `timed_out` |
| `provisioning` | no | `cancel_requested`, `cancelled`, `failed`, `queued`, `running`, `timed_out` |
| `running` | no | `cancel_requested`, `failed`, `queued`, `succeeded`, `timed_out` |
| `succeeded` | yes | - |
| `failed` | yes | - |
| `cancel_requested` | no | `cancelled`, `failed`, `succeeded`, `timed_out` |
| `cancelled` | yes | - |
| `timed_out` | yes | - |

`running -> queued` is the automatic retry of an idempotent job after infrastructure loss.
